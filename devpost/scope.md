# Blind Handoff: scope

## Context and Approval
New local project created 12 October 2026. The learner authorized working on the shortlisted concepts. This plan is an agent proposal based on that concept, not a record of a completed learner interview or approved document. See `docs/skill-pack-evidence.md`.

## Who It Is For
Someone taking over creative or support work who needs to understand a colleague’s instructions. Each exercise contains three cases, which may already be actionable or need clarification.

## The Unique Kernel
Rehearse the handoff from the receiving side. Only the written handoff appears; the outgoing worker's source notes disappear. Identify which specific missing fact blocks the next step, repair it, and run the same rehearsal again.

## The Core Loop
Prepare three incident notes → freeze a handoff → inspect it as the incoming worker → report missing owner, next action or evidence → repair the note → repeat and compare results.

## What Working Looks Like
The original Common Ground starter omits one critical field in each case. The first rehearsal reports three gaps. After deliberate repairs, a second rehearsal has zero structural gaps and the incoming reader explicitly marks each case usable. The result is a rehearsal record, not a safety certification or a claim of real-world effectiveness.

## The POC Boundary
One authoring browser, five fictional work scenarios, three cases per scenario. The twelve added cases cover audiovisual delivery, software support, bookings and studio maintenance. An offline receiver file can be opened separately and return a response by JSON import. No accounts, collaboration backend, operational integration, model API or payment. Local persistence and JSON export support retrying and inspecting evidence.

## Inspiration and Identity
Working name “Blind Handoff”, translation of the proposed “Relevo a ciegas”. The first visual direction was rejected by the learner as too generic. The authorized revision is a focused rehearsal console: white/cool-gray surfaces, ink-blue controls, system sans/mono typography and no landing hero. The work begins at the case queue. Detailed review of the revised experience remains pending.

## Explicitly Cut
Real incidents, employer data, automatic semantic verification, notifications, real shift allocation, clinical or industrial safety claims. These do not help prove the receiving-side rehearsal.

## Pending Learner Decisions
Review the concept and the expanded case library, try the complete loop, and decide whether this is the experience they want. Confirm name and final wording personally before submission.

## 13 October implementation extension

An offline receiver exchange was added to make a separate reader trial possible. Its contents exclude author-only source material; responses must match the frozen file before import. The local journey is explicitly a self-rehearsal. See `../docs/receiver-exchange.md` for behavior, verification and limits. This extension was locally authorized; it does not retroactively complete learner interviews or approve this draft plan.

## 13 October case-library request

The learner explicitly asked for more cases that could plausibly happen in real work. Twelve fictional cases were added, in four selectable collections. Each collection includes missing information, ambiguous or outdated instructions despite filled fields, and an actionable note. Workspaces retain drafts, reports and pending receiver files separately. This request authorizes the expansion; it does not approve the whole plan or establish human validation of the new cases.
