The interaction to inspect

In public/app.js, find case 'start'. It calls makeSnapshot() in public/domain.js. Then incoming() reads the copy, not the editable draft. case 'finish' creates findings. Later edits leave that report unchanged.

The test that protects the idea

In tests/domain.test.mjs, “snapshot and completed report do not change when draft, snapshot or answers mutate” modifies the originals after a report is produced. The saved report must retain the earlier values. That test checks the product promise, not just a function name.

How the comparison stays honest

compareRuns() reads only the two frozen drafts. It distinguishes note text changes from changes in the reader’s judgment. compareContent() shows exact field values and both reader comments. The presentation regression proves that a changed comment remains visible even when the note and blocked field stay unchanged.

A practice to reuse

When a tool must explain what someone saw at a decision point, save an independent record before later edits happen. Write one test that changes the draft afterwards and proves the earlier record stayed intact.

Optional personal exercise after review: change a synthetic next action, rehearse again, and compare the two frozen notes. This is a proposed exercise; it has not been performed by the learner.
